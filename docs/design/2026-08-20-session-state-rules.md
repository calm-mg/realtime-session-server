# 세션 로그인과 방 전이 규칙 설계

## 목적

세션의 반복 로그인과 방 이동 요청이 사용자 정보와 방 구성원을 암묵적으로
바꾸지 않도록 서버 상태 계약을 정의합니다. 연결, 로그인과 방 참가를 명시적
단계로 유지해 서버, 콘솔 클라이언트와 Qt 클라이언트가 같은 규칙을 따르게
합니다.

이 문서는 다음 정확성 작업의 결정과 완료 조건을 기록합니다. 현재 구현의
동작 설명은 [프로토콜](../protocol.md), 작업 순서는
[프로젝트 상태](../project-status.md)를 기준으로 합니다.

## 현재 문제

`RoomService::login()`은 같은 세션의 후속 로그인 요청을 이름 변경으로
처리합니다. `Room`은 참가 시점의 `User`를 값으로 보관하므로, 방에 들어간
사용자의 이름을 다시 로그인으로 바꾸면 사용자 저장소와 방 구성원의 이름이
달라질 수 있습니다.

`createRoom()`과 다른 방을 대상으로 한 `joinRoom()`은 현재 방에서 자동으로
나간 뒤 새 방에 들어갑니다. 그러나 한 요청의 결과에는 새 방 정보만 남아
이전 방 구성원에게 퇴장 event를 보낼 수 없습니다. 서버 내부 상태는 이동해도
클라이언트가 관측한 방 구성원 상태는 일치하지 않을 수 있습니다.

## 결정

### 로그인은 세션당 한 번만 허용

- 연결된 세션의 첫 `LOGIN_REQ`만 사용자를 생성합니다.
- 로그인한 세션의 모든 후속 `LOGIN_REQ`는 이름이 같아도
  `user is already logged in` 오류로 거부합니다.
- 거부된 요청은 user id, 이름, 방 참가 상태와 위치를 변경하지 않습니다.
- 연결을 종료한 뒤 새 세션으로 접속하면 새 로그인이므로 새 user id를
  할당합니다.

`RoomService::login()`은 성공한 `User`만 반환하는 대신 다음 의미의 전용
`LoginResult`를 반환합니다.

```cpp
struct LoginResult {
  bool ok{};
  std::string error;
  domain::User user;
};
```

성공 결과에는 생성한 사용자를, 실패 결과에는 기존 사용자와 오류를
담습니다. `MessageRouter`는 실패 결과를 요청 세션의 `ERROR` 패킷 하나로
변환합니다. 방 동작 필드가 포함된 `RoomActionResult`는 로그인에 재사용하지
않습니다.

### 방 이동은 명시적 퇴장 후에만 허용

- 방에 들어가지 않은 로그인 사용자는 방을 생성하거나 기존 방에 참가할 수
  있습니다.
- 현재 방과 같은 번호로 다시 참가하면 기존 `user is already in room` 오류를
  유지합니다.
- 방에 들어간 사용자가 새 방을 만들거나 다른 방에 참가하면
  `leave current room first` 오류로 거부합니다.
- 다른 방 참가 요청에서는 현재 방 참가 여부를 대상 방 존재 여부보다 먼저
  검사합니다. 따라서 방에 있는 사용자는 잘못된 방 번호를 보내도 현재 방을
  먼저 나가라는 동일한 결과를 받습니다.
- 거부된 요청은 현재 방, 방 구성원, 위치와 lobby의 방 수를 변경하지 않으며
  어떤 방에도 참가·퇴장 broadcast를 보내지 않습니다.
- 성공한 `LEAVE_ROOM_REQ` 이후에는 방 생성과 참가를 정상적으로 요청할 수
  있습니다.

현재 `RoomService` mutex 안에서 검사와 변경을 수행하므로 상태 확인과 전이는
하나의 원자적 작업으로 유지합니다. 자동 이동을 위한 두 방 동시 결과나 새
packet type은 추가하지 않습니다.

## 상태 모델

| 현재 상태 | 요청 | 결과 상태 | 결과 |
| --- | --- | --- | --- |
| 연결됨 | 로그인 | 로그인됨 | 사용자 생성 |
| 로그인됨 | 로그인 | 로그인됨 | 오류, 기존 사용자 유지 |
| 로그인됨 | 방 생성·참가 | 방 참가 중 | 생성·참가 성공 |
| 방 참가 중 | 로그인 | 방 참가 중 | 오류, 사용자와 방 유지 |
| 방 참가 중 | 같은 방 참가 | 방 참가 중 | 오류, 방 유지 |
| 방 참가 중 | 다른 방 생성·참가 | 방 참가 중 | 오류, 방 유지 |
| 방 참가 중 | 방 퇴장 | 로그인됨 | 퇴장 성공 |
| 모든 상태 | 연결 종료 | 연결 없음 | 사용자와 방 상태 정리 |

Qt 클라이언트는 이미 `Connected`, `LoggedIn`, `InRoom` 상태에 따라 로그인과
방 작업을 제한합니다. 이 작업에서는 Qt 상태 모델이나 화면 동작을 변경하지
않고 기존 Controller와 Widget 테스트로 계약이 유지되는지만 확인합니다.

## 변경 범위

- `RoomService` 로그인 결과 형식과 반복 로그인 검사
- `RoomService::createRoom()`과 `joinRoom()`의 현재 방 선행 검사
- `MessageRouter`의 로그인 오류 응답
- 서버 코어의 서비스·라우터 회귀 테스트
- 서버의 현재 규칙을 설명하는 `docs/protocol.md`

packet type, payload framing, room broadcast 형식과 Qt transport는 변경하지
않습니다. 자동 방 이동, 사용자 이름 변경, 재로그인 기반 세션 복구도 범위에
포함하지 않습니다.

## 테스트 시나리오

### `RoomService`

- 같은 이름과 다른 이름의 반복 로그인이 모두 실패하고 기존 user id와 이름을
  유지하는지 검증
- 방 안에서 반복 로그인에 실패한 뒤 채팅과 퇴장이 기존 사용자 정보로
  동작하는지 검증
- 방 안에서 방 생성과 다른 방 참가가 실패하고 기존 방의 구성원과 위치가
  유지되는지 검증
- 거부된 방 생성 때문에 빈 방이나 새 room id가 소비되지 않는지 검증
- 명시적으로 방을 나간 뒤 방 생성과 다른 방 참가가 성공하는지 검증

### `MessageRouter`

- 반복 로그인, 방 안에서 생성과 다른 방 참가가 요청 세션에 `ERROR` 하나만
  반환하는지 검증
- 거부된 방 전이에서 기존 방과 대상 방에 broadcast가 발생하지 않는지 검증
- 명시적 퇴장 후 참가하면 기존 퇴장·참가 응답과 broadcast 순서가 유지되는지
  검증

### 회귀 검증

- `core-dev` build와 전체 테스트
- `format-check`와 가능한 경우 `tidy-check`
- Qt 코드가 바뀌지 않더라도 기존 Controller 상태 테스트가 서버 계약과
  모순되지 않는지 확인

## 완료 조건

- 반복 로그인과 암묵적 방 이동이 상태 변경 없이 명시적 오류로 거부됩니다.
- 실패한 요청 뒤에도 사용자 저장소, 현재 방과 `Room` 구성원이 일치합니다.
- 명시적 퇴장 뒤의 방 생성·참가 경로와 연결 종료 정리가 유지됩니다.
- 서비스와 라우터 회귀 테스트가 오류 응답과 무변경 보장을 검증합니다.
- `docs/protocol.md`가 구현된 로그인과 방 전이 규칙을 설명합니다.
- 프로젝트 상태에서 이 작업을 완료로 이동하고 다음 우선순위를 선택합니다.
