# 프로토콜 버전 협상

## 목적

서로 다른 wire 계약을 사용하는 서버와 클라이언트가 업무 요청을 처리하기 전에
호환성을 확인한다. 협상이 없는 기존 클라이언트는 새 서버에서 거절한다.

## Wire 계약

- 기존 4바이트 header와 최대 packet 크기 4096바이트를 유지한다.
- `VersionReq = 3`: `min_version=1|max_version=1`
- `VersionRes = 4`: `OK|version=1`
- 버전은 1~65535의 ASCII 십진수이며 최소값은 최대값 이하여야 한다.
- 현재 서버와 모든 클라이언트의 지원 범위는 [1, 1]이다.
- 서버는 지원 범위의 교집합에서 가장 높은 버전을 선택한다.
- 요청은 정확히 두 필드, 응답은 정확히 한 필드를 가지며 구조화 문자열
  grammar를 따른다. 잘못된 숫자, 누락·중복·추가 필드는 거절한다.

## 상태와 실패

TCP 연결마다 협상 상태를 새로 만든다. 협상 전에 로그인과 PING을 포함한
다른 요청은 처리하지 않는다. 성공 이후 재협상은 허용하지 않는다.
협상 누락·잘못된 요청·지원 범위 불일치는 ERROR를 전송한 뒤 연결을 닫는다.
실패한 연결에서 뒤따르는 요청은 처리하지 않으며 DB 접근이나 방 변경도 없다.
송신 오류와 queue 포화에서는 기존 연결 격리 정책을 따른다.

클라이언트는 TCP 연결 후 자동으로 협상을 수행한다. 5초 안에 유효한 응답을
받지 못하거나 오류·예상하지 않은 packet·지원 범위 밖의 버전을 받으면
실패를 표시하고 연결을 닫는다. Qt는 협상이 끝나야 로그인 가능한 Connected
상태가 된다. 재접속 시 다시 협상한다. 서버의 무입력 연결은 기존 idle timeout
정책을 적용한다.

## 영향 범위

공용 protocol codec, 서버 router와 연결 종료 경로, Qt application 상태,
콘솔 클라이언트, PING 부하 도구와 시나리오 클라이언트를 함께 갱신한다.
협상 시간은 정상 업무 latency 측정 구간에 포함하지 않는다.

## 검증

숫자 경계와 교집합 선택, malformed payload, 협상 전 업무 요청 차단,
중복 협상, 연결 간 상태 격리와 정리, ERROR 전송 후 종료를 검증한다.
Qt에서는 자동 협상·버전 불일치·응답 timeout·재접속을 검증한다.
Linux 실제 서버 및 부하 시나리오 테스트를 새 연결 절차로 갱신하고
프로토콜 문서와 사용 안내를 같은 변경에서 갱신한다.
