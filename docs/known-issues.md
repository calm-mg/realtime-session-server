# 알려진 문제

이 문서는 현재 코드에서 확인된 결함과 운영상 공백을 추적합니다. 항목을
해결할 때는 재현 테스트를 추가하고, 코드와 관련 문서를 같은 변경에서
갱신합니다. 현재 작업 순서는 [프로젝트 상태](project-status.md)에서만
관리하며, 이 문서에서는 열린 문제와 완료 조건을 설명합니다.

## 구조적 기술 부채

- `RoomService`의 단일 mutex는 서로 다른 방의 작업도 직렬화합니다.
- `TcpServer`는 accept, read, write, backpressure와 shutdown을 한 클래스에서
  조정합니다.

두 항목은 현재 정확성을 우선한 설계이며 즉시 리팩터링하지 않습니다. 실제
부하 측정에서 병목이 확인되거나 기능 추가로 변경 위험이 커질 때 분리합니다.

## 외부 부하 반복에서 소켓 오류 종료 1건

[프로세스·CPU 분리 측정](performance/2026-09-08-external-target/README.md)의
다중 방 조건에서 클라이언트 3회는 모든 메시지를 수신했지만 서버 최종 통계에
상대 EOF 79건과 소켓 오류 1건이 기록됐습니다. 첫 측정 뒤 다음 반복이
진행 중인 주기 snapshot에서 처음 관측했습니다. 통계만으로 정확한 errno와
발생 시점은 확정할 수 없습니다.

작은 송신량의 별도 시스템 호출 추적 반복에서는 재현되지 않았습니다.
클라이언트 종료와 퇴장 알림이 겹쳤을 가능성은 있지만 확인된 원인은 아닙니다.
완료 조건은 원래 조건에서 소켓 errno 또는 패킷 흐름으로 원인을 확인하고,
필요하다면 종료 처리 수정과 재현 테스트를 추가하는 것입니다. 클라이언트
측정 성공과 서버의 소켓 오류 0건을 같은 조건으로 취급하지 않습니다.

후속 [동일 조건 재현 조사](performance/2026-09-08-socket-error-investigation/README.md)에서
변경 전·오류 계측 빌드를 비교했습니다. 오류 경로·errno·시각을 기록하는
`socket_error` 진단을 추가했지만, 기존 1건의 원인을 소급 확정할 수는 없습니다.
강제로 reset을 만드는 회귀 테스트는 진단 경로 검증이며 기존 부하 문제의
재현 증거가 아닙니다. 원인 확인 전까지 이 항목을 열린 상태로 유지합니다.
