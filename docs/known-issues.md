# 알려진 문제

이 문서는 현재 코드에서 확인된 결함과 운영상 공백을 추적합니다. 항목을
해결할 때는 재현 테스트를 추가하고, 코드와 관련 문서를 같은 변경에서
갱신합니다. 현재 작업 순서는 [프로젝트 상태](project-status.md)에서만
관리하며, 이 문서에서는 열린 문제와 완료 조건을 설명합니다.

## 프로토콜과 클라이언트 견고성

### 문자열 payload 구분자와 UTF-8 규칙 부재

응답 payload는 `|`와 `=`로 필드를 구분하지만 사용자 이름, 방 이름과 채팅
입력에 대한 escape 규칙이 없습니다. 이름과 방 이름을 byte 단위로 자르기
때문에 UTF-8 code point 중간에서 잘릴 수도 있습니다.

완료 조건:

- 각 문자열 필드의 최대 UTF-8 byte 수와 허용 규칙 정의
- 구분자 escape 또는 길이 기반·구조화 payload 중 하나를 선택
- 프로토콜 문서와 서버·클라이언트 codec 테스트 동시 갱신
- 한글 경계, 구분자와 최대 크기 입력 테스트 추가

### Qt 메모리 상한 부재

채팅 로그와 Qt 클라이언트의 송신 대기 데이터에 장시간 실행을 위한 명시적
상한이 없습니다.

완료 조건:

- 보존할 최대 로그 항목 수 또는 byte 수 정의
- 오래된 항목 제거 시 모델 notification 정확성 검증
- 송신 대기 byte 상한과 초과 시 사용자 안내 정의

## 구조적 기술 부채

- `RoomService`의 단일 mutex는 서로 다른 방의 작업도 직렬화합니다.
- `TcpServer`는 accept, read, write, backpressure와 shutdown을 한 클래스에서
  조정합니다.

두 항목은 현재 정확성을 우선한 설계이며 즉시 리팩터링하지 않습니다. 실제
부하 측정에서 병목이 확인되거나 기능 추가로 변경 위험이 커질 때 분리합니다.
