# 알려진 문제

이 문서는 현재 코드에서 확인된 결함과 운영상 공백을 추적합니다. 항목을
해결할 때는 재현 테스트를 추가하고, 코드와 관련 문서를 같은 변경에서
갱신합니다.

## 우선순위 1: 정확성

현재 추적 중인 정확성 결함은 없습니다. 방 이동과 반복 로그인 정책은
[프로젝트 상태](project-status.md)의 다음 설계 작업으로 관리합니다.

## 우선순위 2: 운영 안정성

### 프로세스 종료 신호와 정상 종료 미연결

`TcpServer`에는 입력과 출력을 제한 시간 동안 drain하는 `stop()` 경로가
있지만 서버 실행 파일은 `SIGINT`와 `SIGTERM`을 이 요청에 연결하지 않습니다.

완료 조건:

- signal handler에서는 async-signal-safe한 방식으로 종료 요청만 전달
- I/O 스레드가 `stop()` 요청을 관측해 기존 drain 절차를 실행
- `SIGINT`와 `SIGTERM`에서 제한 시간 안에 프로세스가 종료되는 통합 테스트
- 운영 실행 및 종료 방법을 README에 문서화

### `ServerConfig` 검증 범위 부족

queue와 전송 상한은 검증하지만 `max_events`, `backlog`, `idle_timeout` 등
이벤트 루프와 listener 동작에 직접 영향을 주는 값은 검증하지 않습니다.

완료 조건:

- 모든 설정값의 유효 범위를 `ServerConfig::validate()`에서 검사
- 0, 음수와 경계값에 대한 parameterized test 추가
- 설정 기본값과 유효 범위를 서버 구조 문서에 반영

### worker handler 예외 정책 부재

`SessionEventHandler::handle()`에서 빠져나온 예외는 worker 스레드 진입점을
벗어나 프로세스를 종료할 수 있습니다. 기본 handler와 사용자 주입 handler에
동일하게 적용할 정책이 정의되어 있지 않습니다.

완료 조건:

- 이벤트 실패 후 세션 종료, 서버 종료 또는 계속 실행 중 정책 선택
- 예외가 세션 순서 상태와 queue 종료를 손상하지 않는 테스트 추가
- 선택한 정책과 관측 가능한 로그 또는 통계를 문서화

## 우선순위 3: 프로토콜과 클라이언트 견고성

### 문자열 payload 구분자와 UTF-8 규칙 부재

응답 payload는 `|`와 `=`로 필드를 구분하지만 사용자 이름, 방 이름과 채팅
입력에 대한 escape 규칙이 없습니다. 이름과 방 이름을 byte 단위로 자르기
때문에 UTF-8 code point 중간에서 잘릴 수도 있습니다.

완료 조건:

- 각 문자열 필드의 최대 UTF-8 byte 수와 허용 규칙 정의
- 구분자 escape 또는 길이 기반·구조화 payload 중 하나를 선택
- 프로토콜 문서와 서버·클라이언트 codec 테스트 동시 갱신
- 한글 경계, 구분자와 최대 크기 입력 테스트 추가

### Qt 메모리 상한 부재

채팅 로그와 Qt 클라이언트의 송신 대기 데이터에 장시간 실행을 위한 명시적
상한이 없습니다.

완료 조건:

- 보존할 최대 로그 항목 수 또는 byte 수 정의
- 오래된 항목 제거 시 모델 notification 정확성 검증
- 송신 대기 byte 상한과 초과 시 사용자 안내 정의

## 구조적 기술 부채

- `RoomService`의 단일 mutex는 서로 다른 방의 작업도 직렬화합니다.
- `TcpServer`는 accept, read, write, backpressure와 shutdown을 한 클래스에서
  조정합니다.

두 항목은 현재 정확성을 우선한 설계이며 즉시 리팩터링하지 않습니다. 실제
부하 측정에서 병목이 확인되거나 기능 추가로 변경 위험이 커질 때 분리합니다.

## 해결된 문제

### Qt transport 오류 후 연결 상태 불일치

2026-08-20에 해결했습니다. 복구 가능한 요청 오류와 연결을 종료하는 오류를
구분하고, fatal 오류는 실제 소켓과 버퍼를 정리한 뒤 Controller 상태를
초기화합니다. 큰 outbound payload, 연결 실패, 수신 프로토콜 오류 후 재연결,
원격 종료와 전송 실패 시 채팅 입력 보존을 Qt 회귀 테스트로 검증합니다.

### 동일한 방 재참가 시 Lobby 상태 불일치

2026-08-20에 해결했습니다. 동일한 방 재참가는 `user is already in room`
오류로 거부하며, 마지막 멤버와 여러 멤버 상황에서 기존 방 상태가 유지되고
이후 채팅과 방 나가기가 정상 동작하는지 회귀 테스트로 검증합니다.
